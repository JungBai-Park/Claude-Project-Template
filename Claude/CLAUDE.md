# 폴더 구성

1. Documents\\ :
   이 폴더 밑에 적히는 문서들은 여러 세션에 걸쳐 AI가 프로젝트를 이어서 완성하기 위한 기록이다.
   **사용자가 읽는 문서가 아니며, 사용자에게 설명하려고 쓰지 않는다.** 따라서, mermaid-writer 스킬 호출도 하지 않는다.
	- DESIGN.md :
	  설계 내용 문서의 목록을 기록하는 문서
	- DESIGN\\ :
	  설계 내용에 대한 각각의 세부 사항들이 보관되는 폴더
	- PITFALLS.md :
	  함정·트러블슈팅 문서의 목록을 기록하는 문서
	  함정·트러블슈팅이란 프로젝트 진행 중 발생한 주요 실수, 시행착오와 그 해결 방법이다.
	- PITFALLS\\ :
	  함정·트러블슈팅에 대한 각각의 세부 사항들이 보관된 폴더
	- PROGRESS.md :
	  개발 진척 상황 문서 운영 지침 및 목록을 기록하는 문서
	- PROGRESS\\ :
	  개발 진척 상황에 대한 각각의 세부 사항들이 보관되는 폴더
	- MEMORY\\ :
	  autoMemoryDirectory 설정값으로 지정된 위치.
	  "마무리" 때 DESIGN, PROGRESS, PITFALLS 문서에 반영되어야 하는 내용은 MEMORY에 저장하지 않는다.
	  그 외의 내용(사용자에 대한 정보, 작업 방식에 대한 사용자의 지적과 선호, 외부 자료의 위치 등)만 MEMORY에 저장한다.
	  MEMORY는 클로드 코드가 스스로 내용을 관리하는 방식이므로, "마무리" 명령과 무관하게 작성된다.

2. Source\\ :
   프로그램 제작에 필요한 파일들이 저장된 폴더
	- Code\\ :
	  사용자와 AI가 만든 소스코드
	  배포용 실행파일을 만들기 위한 코드(또는 배포 시 실행되는 코드)이므로, Test\\ 폴더의 코드를 호출하지 않아야 한다.
	- Data\\ :
	  프로그램 실행 시 참조되는 데이터
	- Test\\ :
	  테스트 목적으로 만들어 놓은 코드. (단, 보존 가치가 있는 코드만 여기에 두며, 1회성으로 쓸 코드는 Temp\\에 만든다.)
	- Build\\ :
	  개발환경(IDE)의 프로젝트 설정파일
	  실행파일 및 실행파일 제작을 위한 중간 산출물
	  사용자가 신경 쓰지 않아도 되는 소스코드 (IDE 자동생성코드, 제3자 제공코드, 오픈소스)

3. Temp\\ :
   임시 파일은 시스템 스크래치패드에 만들지 않고 이 Temp\\ 폴더에 만든다.
   세션 종료 후 깨끗이 지워져도 상관없는 파일만 둔다.
   Temp\\에 어떤 파일을 생성/삭제/변경했다고 보고할 필요는 없다.

4. Reference\\ :
   참고용 파일
   사용자가 관리하는 폴더이며, 불필요한 파일은 수시로 삭제될 수 있다.

# 진척상황 보고

- 사용자가 "진척" 또는 "PROGRESS"에 대해 묻거나 브리핑을 원하면(예: "진척 상황 보고", "진척 현황 보고", "진척?", "PROGRESS?") `Documents\PROGRESS.md`의 "진척상황 보고" 항목을 읽고 그대로 따른다.
- 세션 진행 중 "마무리"를 포함해 어떤 이유로든 PROGRESS.md의 업무 목록을 수정했으면, 수정을 마친 직후 진척상황 보고를 자동으로 수행한다.
- 사용자는 PROGRESS, DESIGN, PITFALLS 문서를 제목이나 번호로 가리킨다. "6번 업무"는 `PROGRESS\006_…`, "6번 설계"는 `DESIGN\006_…`, "6번 함정"은 `PITFALLS\006_…`이다. 진척상황 보고 직후 종류 없이 "6번"이나 "006번"만 말하면 업무다.
- 사용자는 번호를 다 외우고 있지 않으므로, AI는 사용자와의 대화에서 번호만 말하지 말고 번호와 제목을 함께 말한다.

# 파일 및 디렉토리의 생성 규칙

1. 승인 없이 파일 및 디렉토리를 생성 가능한 폴더 :
   AI가 파일 및 디렉토리를 생성할 때는, 그 목적에 따라 Documents\\의 하위 디렉토리(DESIGN\\, PROGRESS\\, PITFALLS\\, MEMORY\\),
   Source\\의 하위 디렉토리(Code\\, Data\\, Test\\, Build\\) 그리고 Temp\\에 배치할 수 있다.
2. 그 외의 폴더 (예: 프로젝트 루트, Source\\ 바로 밑, Documents\\ 바로 밑, Reference\\ 내부)는 사용자의 승인을 받아야 한다.

# 문서의 작성 및 갱신 규칙

1. 토큰 절약을 위해 불필요한 내용(더 이상 유효하지 않은 설계 내용, 취소된 계획 등)을 적어 두지 않는다.
2. 특히, 다음과 같이 적지 않도록 주의한다.
	- BAD(이 값은 2026년 11월 07일, 3에서 4로 바뀌었다.) -> GOOD(이 값은 4이다.)
	- BAD(전에는 이렇게 하기로 했으나 2026년 11월 07일 더 이상 하지 않기로 했다.) -> GOOD = 삭제
3. 문서 작성 및 갱신은 "마무리" 때 일괄로 한다.
	- 다음과 같은 상황에서도 문서에 즉시 반영하지 않고, 세션 종료를 위한 "마무리" 요청 때 문서에 반영한다.
		- 사용자와의 대화를 통해 설계 내용이 결정되었을 때
		- 작업 중 함정(PITFALL)을 만나 우회방법으로 처리했을 때
		- 작업 후, PROGRESS.md의 완료·미완료 표시
		- 파일을 옮기거나 이름을 바꿔 문서에 적힌 경로가 어긋나는 것이 발견된 경우
	- 예외는 사용자가 특정 사항을 문서에 반영하라고 명시적으로 요청한 경우뿐이다. 이때도 요청한 사항만 반영한다.

# Issue 상황 대화 방법

1. Issue 상황이란, 개발과정에서 사용자와의 협의를 필요로 하는 내용이 발생한 상황을 말한다.
2. AI는 사용자가 올바른 판단을 할 수 있도록 다음과 같은 정보를 제시하며 질문을 한다.
	- 발생 조건 : 어떤 경우(입력, 사용 상황, 문서 형태)에 그 issue가 발생하는가?
	- 문제점 : 발생하면 무엇이 왜 문제인가? (잘못된 결과, 오류, 판단하지 못하는 지점 등)
	- 용어 설명 : 질문에 사용된 용어에 대해 설명 (사용자가 알고 있다고 생각되는 경우는 생략)
3. Issue 사항을 다음에 검토할 수 있도록 문서에 반영할 때,
   현재 세션의 문맥(context)을 모르는 다음 세션이 해당 issue를 사용자와 대화하기 위해 필요한 모든 정보를 적어 둔다.
