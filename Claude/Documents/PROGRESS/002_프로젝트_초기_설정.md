# 업무 개요

* 템플릿(`D:\Tools\Commands\New\Claude`)을 복사해 새 프로젝트를 시작할 때 처음 한 번 해야 할 일이다. 템플릿 상태의 문서들을 프로젝트 목적에 부합하도록 수정한다.
* 앞 번호가 뒤 번호의 전제이므로 번호 순서대로 진행한다.
* `DESIGN.md`, `PITFALLS.md`, `PROGRESS.md`와 그 세부 문서(`DESIGN\003_개발환경.md` 포함)는 "마무리" 때 일괄로 갱신하는 규칙이므로 최초 작업에서 채우지 않는다.
  1·2번에서 사용자가 알려 준 목적과 결정은 마무리 때 해당 주제 문서의 `# REQUIREMENTS`에 기록한다.

# 세부 업무 목록

- [ ] **1. 프로젝트의 목적 파악 :**
	- 사용자에게 프로젝트가 무엇을 하는 것인지 묻는다.
- [ ] **2. 프로젝트 이름 정하기 :**
	- 사용자가 이름을 말해 주지 않으면 폴더 이름을 제안하고 확인받는다.
	- `CLAUDE.md`의 `# 프로젝트 개요`에 있는 "이름 : (작성 예정)"을 정해진 이름으로 바꾼다.
- [ ] **3. `autoMemoryDirectory` 고치기 :**
	- 템플릿을 복사하면 `.claude\settings.json`의 `autoMemoryDirectory`가 **템플릿의 메모리 경로(`D:\Tools\Commands\New\Claude\Documents\MEMORY`)를 그대로 가리킨다.**
	  고치지 않으면 새 프로젝트의 메모리가 템플릿 폴더에 쌓이고 다른 프로젝트와 섞인다.
	- 이 프로젝트의 `Documents\MEMORY` 절대 경로로 바꾼다. 경로의 `\`는 JSON에서 `\\`로 쓴다.
	- 바꾼 설정은 바로 적용되지 않을 수 있다.
	- 바꾼 뒤 `CLAUDE.md`에 있는 "템플릿 사용 시: `autoMemoryDirectory`를 …" 안내 줄을 지운다.
- [ ] **4. 개발 언어와 IDE 결정, `Source\Build\` 정리 :**
	- 사용자와 함께 개발 언어와 사용할 IDE를 정한다. 정해지지 않았으면 정해지지 않았다고 적고, 임의로 고르지 않는다.
	- 정해진 개발 환경에서 `Source\Build\`가 필요 없으면(컴파일·링크 단계나 IDE 프로젝트 파일이 없는 경우, 예: Python) 이 폴더를 삭제한다.
	  삭제했다면 `CLAUDE.md`에서 `Source\Build\` 관련 내용을 지운다.
	- 필요하면 그대로 둔다.
	- 이 결정은 5번, 6번, 7번의 전제이므로 먼저 한다.
- [ ] **5. `Source\파일정리.bat` 수정 :**
	- 템플릿에는 `Source\파일정리.bat`가 0바이트 파일로 이미 만들어져 있다. 4번에서 구체화된 개발 환경에 맞춰, 중간 산출물을 제거하도록 이 파일을 수정한다.
	- 제거 대상은 해당 언어와 IDE가 컴파일·링크 과정에서 만드는 중간 결과물이다. 소스, 프로젝트 파일, 설정, 실행파일을 지울지는 개발 환경이 정해진 뒤 사용자와 정한다(추정으로 지우지 않는다).
	- `.bat` 파일은 CP949(BOM 없음)+CRLF로 저장해야 하므로 `cp949-crlf-edit` 스킬 방식으로 수정한다.
	- 개발 환경에서 제거할 중간 산출물이 없으면 파일을 수정하지 않고, 수정하지 않은 이유를 사용자에게 알린다.
- [ ] **6. `.gitignore` 최신화 :**
	- 4번에서 구체화된 개발 환경에 맞춰 `.gitignore`를 고친다. 언어와 IDE가 만드는 중간 산출물 패턴을 추가하고, 5번의 `Source\파일정리.bat`가 지우는 대상과 어긋나지 않게 한다.
	- 민감 파일과 실행파일의 git 추적 여부는 템플릿에서 정하지 않은 사항이다. 이 단계에서 사용자와 함께 정한다.
- [ ] **7. `CLAUDE.md`의 "작성 예정" 항목 채우기 :**
	- `# 프로젝트 개요`의 "목표 :" 아래에 프로젝트 목표를 한두 문단으로 쓴다. 아직 정해지지 않은 사항은 정해지지 않았다고 쓴다.
	- "용어 정의"에 이 프로젝트에만 해당하는 용어를 쓴다. 지금 알 수 있는 것만 쓴다.
	- "규칙"에 이 프로젝트에만 해당하는 규칙, 환경, 금지 사항을 쓴다. 지금 알 수 있는 것만 쓴다.
	- 개발 환경(도구 설치 현황)은 `CLAUDE.md`가 아니라 `DESIGN\003_개발환경.md`에 적는 내용이므로 여기서 채우지 않는다.
- [ ] **8. 옵시디언에 볼트로 등록 :**
	- `Documents\` 폴더는 옵시디언 볼트(`Documents\.obsidian`)다.
	  복사한 새 프로젝트의 `Documents\`를 옵시디언 프로그램에 볼트로 등록해야 한다.
	  이 폴더의 문서는 아주 예외적인 상황이 아니면 사용자가 읽지는 않는다. (예외적인 상황을 대비해 옵시디언에 등록한다.)
	  등록은 사용자가 직접 하는 일이므로 AI가 사용자에게 알린다.
	- 방법: 옵시디언에서 "폴더를 볼트로 열기"(Open folder as vault)를 선택하고 이 프로젝트의 `Documents\`를 고른다.
	- 등록하지 않으면 사용자가 AI 전용 기록 문서(`DESIGN`, `PROGRESS`, `PITFALLS`)를 옵시디언으로 열어 볼 수 없다.
- [ ] **9. 완료 처리 ("마무리" 때) :**
	- `PROGRESS.md`의 "현재 진행 중인 업무"에 있는 이 문서의 줄을 "완료된 업무"로 옮기고 `[x]`로 표시한다. (이 문서는 삭제하지 않고 보존한다.)
	- 이 문서의 맨 위에 "완료됨"을 표시하고, 실제로 정한 프로젝트 이름과 목적, 바꾼 설정, 채운 항목, 볼트 등록 여부를 간단히 적는다.
